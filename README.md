# MBT: My Budget Tracker

Офлайн-приложение (PWA) для личных финансов: счета, операции, помесячный бюджет,
долги, цели, дни без трат и годовая аналитика. **Local-first / zero-backend**:
все данные хранятся на устройстве (IndexedDB), серверной части нет.

## Стек
React 19 · TypeScript (strict) · Vite · Tailwind CSS v4 · Dexie (IndexedDB) ·
vite-plugin-pwa (Workbox) · Vitest · oxlint

## Команды
```bash
npm ci
npm run dev        # разработка
npm run lint       # oxlint
npm test           # Vitest
npm run test:coverage  # покрытие (src/domain/** — порог 100%)
npm run build      # tsc + vite build + сервис-воркер
npm run preview    # проверка production-сборки (в т.ч. офлайн)
```

## Сохранность данных
| Уровень | Что делает |
|---|---|
| L1 | `navigator.storage.persist()` при запуске — защита от автоочистки |
| L2 | Автобэкап в выбранный файл (File System Access API, Chromium). После перезапуска браузера доступ нужно подтвердить кнопкой «Возобновить автобэкап» |
| L3 | Ручной экспорт/импорт JSON (работает везде, включая iOS Safari) |

В бэкап не попадают ссылка на файл автобэкапа и локальные статусы. «Полный сброс» также
отвязывает файл автобэкапа, чтобы пустое состояние не перезаписало вашу копию.

## Решения и ограничения
- **Валюты:** капитал и аналитика считаются в KZT по текущим курсам (не по курсу на дату операции).
  Курсы берутся из [nbk-rates](https://github.com/al-writer/nbk-rates) — архива официальных курсов НБ РК
  (GitHub Pages, обновляется дважды в сутки): приложение запрашивает `latest.json` при запуске и по кнопке
  «Обновить курсы». Это единственный внешний запрос; офлайн используются сохранённые или введённые вручную
  курсы. Адрес можно сменить при сборке переменной `VITE_RATES_URL`. Счета в валюте без курса в капитал не входят.
- **Долги и цели** ведутся в тенге: платёж/пополнение — только со счетов KZT.
- **Платежи по долгам и пополнения целей** не нарушают «дни без трат».
  Пополнения целей не считаются тратами бюджета и остаются «сбережениями» в аналитике.
- **Лимит на сегодня** = (план месяца − траты месяца) / оставшиеся дни, включая сегодня.
- Даты — по локальному часовому поясу устройства.

## Публикация (GitHub Pages)
Деплой запускается автоматически при каждом push в `main` (`.github/workflows/deploy.yml`:
lint → test → build → публикация). Адрес: `https://<owner>.github.io/<repo>/`.

На корне сайта — лендинг (`index.html`, код в `src/landing/`), само приложение — в подкаталоге `app/`
(`app/index.html`, адрес `https://<owner>.github.io/<repo>/app/`). Сервис-воркер и манифест ограничены `app/`,
лендинг в офлайн-кэш не попадает. Локально: `npm run dev` → `http://localhost:5173/app/`.

Инструкция — `docs/index.html` (код в `src/docs/`), адрес `…/<repo>/docs/`. Скриншоты для неё
лежат в `public/docs/img/` и пересоздаются на демо-данных (нужен Playwright с Chromium):
```bash
node scripts/docs-screenshots.cjs
```

Один раз в репозитории: **Settings → Pages → Build and deployment → Source: GitHub Actions**.

Подпуть задаётся переменной `BASE_PATH` (в workflow — `/<repo>/`, локально — `/`):
```bash
BASE_PATH=/PWA-Budget/ npm run build && BASE_PATH=/PWA-Budget/ npm run preview
```
Навигация на хэшах (`#/budget`), поэтому SPA-fallback не нужен. Данные привязаны к адресу сайта
(origin), поэтому при смене домена перенесите их через экспорт/импорт JSON.
